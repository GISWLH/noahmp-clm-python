## 问题与方法边界

当前被动库标准周转时间270年，环境调节还会降低分解速率；逐年等待所有慢库
平衡成本很高。CLM5官方给出相同CENTURY型周转时间，并将加速分解与退出时
库量转换分开处理，不能只把周转时间改小后当作正常模式平衡。
参考[CLM5分解技术说明，表2.21.3及2.21.8节](https://escomp.github.io/CTSM/release-clm5.0/tech_note/Decomposition/CLM50_Tech_Note_Decomposition.html)。

本试验保留标准速率，研究周期库量初始化这一更窄问题。先稳定植物输入、
解析估计慢库、再恢复完整耦合收敛，是已有半解析spinup研究的分阶段思路；
本文没有复现其完整CABLE算法，也不沿用论文的加速倍数。
参考[Xia等，2012，方法摘要](https://gmd.copernicus.org/articles/5/1259/2012/gmd-5-1259-2012.html)。

给定每天土温、水势及凋落量，且每天氮限制因子恰为1时，七库碳量满足
`C_next = A_day (C + u_day)`。独立写出的库间转移矩阵P与损失率构成
`A_day = I + (P - I) diag(1 - exp(-r_day × dt))`。按原时间顺序合成一年
`C_end = M C_start + b`，求解`(I - M) C_periodic = b`。
该线性条件来自规定的环境和输入；植物生长、叶氮、矿质氮限制、水热反馈均
可能破坏它，不能把此解直接称为完整单柱平衡。

输入按固定正弦季节变化，木本另有0.08 gC/m²/day粗木输入。完整公式和参数
随脚本公开，未读取FLUXNET评分或选择站点高度。

## 氮限制负对照与后续

无氮限制案例将矿质N初态设为1e6 gN/m²，仅用于隔离算子条件，不能作站点
初态。负对照改为矿质N=0、库C:N=100及低N凋落输入；两例氮限制因子均最低
达到0，生产C库与条件线性解最大偏离148.3820/126.1900 gC/m²。因此当前
方法不接受缺氮实际柱；没有把负对照差异通过裁剪或放宽容差隐藏。

后续需使用完整气候驱动及已经稳定的实际植物输入，保留N限制和叶氮反馈，
再判断是否能构造透明的新初始化方案。任何新初态须记录独立来源、原配置
及初始C/N存量，不能冒充旧检查点续算或用人为通量冲销库量。最终仍须正常
模式真实循环，并由[气候循环评价入口](CLM_SPINUP_ASSESSMENT.md)核对原水热、
守恒和土壤碳漂移条件。当前生产代码、站点初态和在跑年度均未修改。

首轮PBS101因诊断脚本两处Python `abs(list)`调用报TypeError并退出1；修订B
仅改为`numpy.abs`及新的输出名，PBS102退出0，488份冻结源前后哈希一致。
原失败未覆盖，不是物理模块错误，也没有增加一项生产物理功能。
