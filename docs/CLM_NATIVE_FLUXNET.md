# 原生完整柱真实站点运行器

`benchmarks/run_fluxnet_native.py`把已有BGC/MOST设备柱接到与NumPy运行器相同的
显式站点配置和准备好的强迫。每个批量列独立携带全部16个数组，包括五层雪、
四层土壤、十层冠层凝结物、物候及植物/土壤C/N；更新强迫时仅替换CO₂、太阳角
和散射比例，不覆盖预报LAI或氮因子。未改变物理参数、迭代容差和验收门。

同一批量允许不同站点/年份的独立时间轴，但步数须相同，叶片参数须相同。
不同叶片参数分批执行。此入口使用自然植被的16数组ABI，不用于作物种子、
灌溉待处理水量或湿地甲烷；这些扩展已有各自的设备入口，不能省略它们的状态。

## 守恒、检查点和评价身份

- 主机float64独立重算降水相态/焓、实际辐射及H/LE，核对M/H/C/N及五种雪杂质；
  冠层使用10层权威状态求和。每柱单独计算数值界，不采用批量最大界，也不允许
  不同柱残差相互抵消。整柱累计账与逐步账同时保存。
- 每48步及退出时保存原生16数组、累计输入/界、轨迹和SHA256；`--resume`严格
  校验批配置、源代码、CUDA源、雪查表数据、强迫、配置、检查点和轨迹身份。
- `--compare-jax32`在CUDA32之外独立携带JAX32状态，逐步核对全部返回字段和
  土壤温度/液水；整数一致，浮点`rtol=atol=1e-6`。JAX轨迹不重置成CUDA结果，
  也有自己的逐步/累计守恒检查。
- 部分轨迹仍标`running`，失败标`failed`。仅全部请求步完成才标`complete`。
  输出兼容严格FLUXNET评价器，包含各站实际量化后的初始土壤水/焓及几何，明确
  输入量化精度。后端一致不能代替站点观测、spinup或留出验收。

批配置示例（路径相对该JSON；可指定绝对路径）：

```json
{"cases": [{"case": "CN-Cng-tq6-w2", "input": "CN-Cng.npz",
  "input_manifest": "CN-Cng.json", "configuration": "configs/CN-Cng-tq6-w2.json"}]}
```

```sh
PYTHONPATH=src:benchmarks python benchmarks/run_fluxnet_native.py \
  --batch height-batch.json --output native-run --backend cuda32
# 从完整保存的上一代状态继续；短检查使用 --stop-after N。
PYTHONPATH=src:benchmarks python benchmarks/run_fluxnet_native.py \
  --batch height-batch.json --output native-run --backend cuda32 --resume
```

## 跨强迫段接续与保存中断恢复（2026-10-17）

`--initial-run`指向一个已完整结束的原生运行目录，必须同时指定
`--initial-mode continue`或`cycle`。continue要求每柱新旧时间轴严格连续；
cycle只允许同一完整日历年块的原强迫与原清单重复。两种方式均要求相同的
后端、影子设置、全部源码、案例顺序和配置哈希；改变参数或重新排序不能混入
接续。循环仅提供气候重复执行能力，**不自动认定达到spinup平衡**。

全16数组从前段末态直接携带，累计M/H/C/N初始库、净输入、数值界和残差最大值
继续沿用最初起点；JAX影子也独立携带自己的状态与账。每段观测时间轴与轨迹
重新开始，土壤观测算子使用实际接续初态。输出记录上一段报告/检查点哈希、
跨段步数及段数。续跑这类段时须再次提供相同的initial参数。

保存改为唯一代次的状态、轨迹及逐柱报告先写完，再以单次原子替换提交批量
索引。`report.json`仅是提交后的便利副本；恢复读取索引绑定的不可变报告，
不依赖可能中断或过期的副本。旧格式继续严格校验，遇到混合代次会拒绝，
不会猜测应采用哪个状态。进程中断恢复与磁盘/整机断电的持久性保证不同；
本次未做断电实验。

```sh
PYTHONPATH=src:benchmarks python benchmarks/run_fluxnet_native.py \
  --batch next-year.json --output next-year-run \
  --initial-run previous-year-run --initial-mode continue
```
