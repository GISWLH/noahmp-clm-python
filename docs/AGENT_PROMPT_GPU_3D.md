## K1. residual 569 项：取证 + 混合精度割线（约 2–3 小时，第一优先）

现状：候选 residual 绝对容差 2e-3 仍有 569 项超差，且 H/LE/G 也有超差——
**2e-3 提案已证伪，不要再提它。** 按以下步骤走：

1. **取证**：把 569 项全部 dump 出来，每项带完整上下文——哪个诊断、
   哪个柱配置、哪一步、当时状态（有雪？冻土？土壤水近萎蔫点？
   通量近零？）。写 `docs/GPU_RESIDUAL_FORENSICS.md`：按诊断×状态聚类，
   给出直方图/表格，回答一个问题：超差是**均匀分布**（系统性 bug）
   还是**聚集在相变时刻**（雪起/融、冻融、干湿切换）？
2. **混合精度割线原型**（新思路）：残差来自割线求解，而割线是每柱标量
   迭代——原型一个变体 kernel：**割线求解（F 求值 + 迭代）在 float64
   下做，其余批量物理保持 float32**。测两点：① residual 与 numpy64 的
   差距是否 →0（或只剩相变聚集项）；② 成本（割线是标量工作，
   overhead 应 <10%，实测为准）。
   - 若差距 →0 且成本可接受：采纳为生产 kernel 设计，文档写清理由
     （"精度关键路径用 float64，批量物理保持 float32"是标准做法，
     不是作弊）；重新跑 H4。
   - 若差距仍在：回到取证结论，按"相变聚集"处理（见第 3 条）。
3. **分档容差的最终处理**：只有在 K1 第 1–2 步证据齐全后，才可基于
   推导提出分档方案；**任何容差变更必须经 Wang 明确确认**，
   在此之前 H4 保持红灯。不要把"候选"写成"结论"。

## K2. 年度预检第 3 天失败：根因（约 2 小时，可靠性第一门）

这是最重要的可靠性信号——第 3 天就失败的模型不能用于真实模拟：

1. 复现年度预检，开**逐日（必要时逐时）状态 dump**，找到第一个
   发散的步/日。
2. 定位变量：检查 NaN、负土壤水、负 swe、雪层数异常、地下水位发散、
   土壤冰含量超界。怀疑对象按优先级：首次降雪时的雪层分层/合并、
   首次冻结时的冻土反推、土壤水近萎蔫点的根系胁迫、TOPMODEL 地下水位。
3. 最小复现：单柱 + 失败配置 + 失败强迫切片，复现后修。
4. **关键判断**：若第 3 天失败在 numpy 普通版里同样复现——这是基线
   物理/数值 bug，不是 GPU bug，修在普通版源头，修完重新跑 parity；
   若仅 GPU 版失败——修 GPU 版。
5. 修完重跑完整 365 天。交付：`docs/GPU_ANNUAL_FIX.md`（根因、修复、
   重跑结果）→ commit + push。
