# 降水至排水的原生 CLM 质量/焓柱

本检查点连接已经实现的 NumPy `step_clm_enthalpy_column`，保留完整质量、焓和
雪中五类杂质状态。原生 JAX/CUDA 计算降水分相、液水截留、降雪重分层、
降雨入渗、冠层/雪/土壤表面交换、融雪、重力排水及气候态沉降。
这是开发入口；冠层截雪/冻结、MOST 通量反馈、默认驱动切换和外部科学验收
仍待完成。现有液水截留容量与选项 1–4 径流分类保持 NumPy 原实现。

## 接口与物理顺序

`gpu.clm_enthalpy_column.pack_clm_enthalpy_columns` 编码状态，
`step_clm_enthalpy_columns_jax` 与
`gpu.cuda.clm_enthalpy_column.step_clm_enthalpy_columns_cuda` 推进独立柱。
没有用主机 NumPy 回算任何设备物理，也不调用已发布三层雪/温度柱的推进器。
旧模块只提供降水分相、地面阻抗、阻力速度及水分胁迫函数。

输入批量首轴为独立柱数，其余形状为：雪 `(5,9)`、土壤 `(4,3)`、土壤参数
`(6,)`、整数选项 `(9,)`、站点参数 `(12,)`、冠层水/焓及旧表温 `(3,)`、
根权重 `(4,)`。土壤单元保存水量 kg/m²、焓 J/m²、厚度 m，支持任意四层
厚度。状态不压缩回 v0.2 的 70 浮点旧 ABI。具体字段由源码中的
`OPTION_NAMES`、`SITE_NAMES`、`DIAGNOSTICS` 明确列出。

强迫形状 `(N,8)`，依次为 `dt, tair, qair, wind, ps, swdown, lwdown, prcp`；
降水单位 m/s。可选沉降 `(N,5)` 为 BC 加四档尘埃，单位 kg/m²/s。
返回 `snow_cells, soil_cells, options, storage` 用于下一步，参数、站点及根权重
保留。`return_surface=True` 附带排水/沉降前的表面求解器诊断，以支持独立审核。

1. 按已支持的降水选项 1–3 分相，并计算雨/雪携入焓。先路由旧冠层超容量水，
   再截留新降雨；降雪直接到地面，雨水进入雪或土壤。
2. 根据更新后的土壤水热诊断胁迫和交换参数，调用已验证的原生非线性表面步。
3. 路由最后的冠层溢流及其焓，处理雪排水和土壤准入，再推进重力排水。
4. 施加气候态沉降；无雪时沉降作为离开雪系统的杂质量显式返回。
5. 按最终雪/土壤状态更新下一步表温，分类实际径流，并核算整柱收支。

进入已有雪层的液态水直接相加其权威质量与焓，避免先把携热换成雨温再换回
焓的多余舍入。未改变物理参考焓原点或裁掉融尽后的余热。水、焓与杂质收支
分别以完整初末储量和外部输入/输出独立重算；内部滴落和融水不当作外部源。

## 验证及未完成项

早期冻结 `b` 的目标测试 **4 passed / 0 skipped，224.39 秒**，16 类工况
覆盖降雨、降雪、雪上雨、融尽、霜露、冠层超容量、裸地、五层雪、不同土层厚度、
已有选项组合及极低 LAI。CUDA32/JAX32 全字段最大绝对差
**4.768372e-7**，满足保留的 `rtol=atol=1e-6` 门。
float32 独立单步最大水/焓/杂质残差为
**4.761294e-5 kg/m² / 76.152564 J/m² / 4.302114e-16 kg/m²**；
JAX64 为 **1.182110e-13 kg/m² / 0.001388688 J/m² / 0**。
逐工况按分层求解容差及浮点储量精度检查，没有以 10% 物理误差豁免守恒。
最大水/焓数值界分别为 float32 的 0.007013702 kg/m² / 3466.499526 J/m²，
JAX64 的 1.306404e-11 kg/m² / 0.001404545 J/m²；这些界不是实际残差。

冻结 `c` 补充了明确的混合雨雪工况，并让非标准土层厚度用到依赖厚度的
地面阻抗和径流选项。最终目标 **4 passed / 0 skipped，166.87 秒**；
同精度最大绝对差仍为 **4.768372e-7**，最大独立收支残差同上。

首轮冻结 `a` 在检查饱和土层温度时失败：设备返回质量 45 kg/m²，严格 double
构造器对量化孔隙度/层厚的乘积检查超出约一个 float32 ULP。诊断改为先检查
8ε 的表示精度界，再用 SciPy `brentq` 直接反演原质量/焓方程；**不修改状态、
水量、焓或物理验收阈值**。原失败日志和源码完整保存。此修改只影响测试中的
独立温度诊断，真实设备计算没有因此截水或改参数。

连续审核入口 `benchmarks/check_clm_enthalpy_column_gpu.py` 比较 NumPy64、
JAX64、JAX32、CUDA32，在相同量化强迫下推进三类独立柱七天，含周期降水、
冻融及沉降。核查日 ET/H/LE/GPP、土壤温湿、径流、SWE 与逐步/累计收支。
合成后端对照不能替代 CLM5/HRLDAS 官方输出、FLUXNET 或实测雪验证。
