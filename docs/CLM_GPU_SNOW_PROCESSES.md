# 雪表层水汽、霜露与微结构：原生后端

2026-10-14：`gpu.snow_vapor` / `gpu.cuda.snow_vapor` 实现表层冰/液水
混合相汽化、霜和露的质量/焓交换；`gpu.snow_evolution` /
`gpu.cuda.snow_evolution` 实现压实、干湿粒径老化、再冻结粒径混合、
黑碳/四类尘埃沉降及新雪密度/粒径诊断。NumPy 参考为此前的
`physics.snow_vapor` 和 `physics.snow_evolution`。
这仍是组件验证，完整冬季冠层/土壤水文设备连接及观测验收尚未完成。

## 过程与接口

`pack_snow_vapor` 使用与[质量输送](CLM_GPU_SNOW_MASS.md)一致的五层
质量、焓、厚度、粒径和五类杂质状态。`run_snow_vapor_jax/cuda` 接受
有符号交换量：正数按表层冰/液水比例移除，负数依据表温形成霜/露。
潜热 `Lv*mass + Lf*ice` 与随凝结态质量输送的焓分别输出，调用者不能
把潜热再从雪焓中扣除一次。霜带来 200 kg/m³ 的新增体积，考虑再冻结
膨胀。最后一层耗尽时显式返回杂质残留；空雪柱上的露由土壤处理。

表层耗尽沿用原 NumPy 求解器的 64 epsilon 相对舍入界，按后端状态精度
缩放，并输出实际移除量。只用于恰好耗尽附近的表示误差，超供水需求
仍拒绝。参考检查使用同一有界耗尽规则，未用 clipping 接受真实过抽。
`remap=False` 可保留热过程网格，便于完整柱在相变后统一重分层。

`pack_snow_evolution` / `run_snow_evolution_jax/cuda` 的操作为压实、
老化、沉降或压实后老化。组合入口与现有 NumPy 冬季柱一致：先压实，
再用更新后的密度老化，最后按请求重分层。融前冰量和再冻结量均为
调用者传入的同网格历史，不从最终雪量倒推出有利的历史值。
温度梯度、气候态沉降速率也作为输入；没有新增气溶胶传输。

老化使用原 UCAR 三维参数表（11 温度 ×31 梯度 ×8 密度），设备执行
三线性插值。干增长用其速率方程的解析积分，湿增长用半步干/整步湿/
半步干分裂。液水质量比上限 0.1、再冻结光学面积混合及 30–1500 µm
粒径限制与 NumPy 一致。超查表范围会输出逐层标记。数据来源与旧单位
属性核查见[雪设计记录](CLM_SNOW_DESIGN.md)，未复制 CTSM 物理源码。

## 查表节点的数值缺陷

初次全表检查在 85 个节点发现双精度粒径差超过 1e-5 µm。最大例子为
T=228.15 K、梯度 250 K/m、密度 300 kg/m³：温度加减冰点时产生
**−2.842171e-14 K** 舍入，NumPy 将邻点混入本节点，使 tau 从表中
**1.919972e-26** 变为 **1.357993e-15**。tau 跨约 39 个数量级，不能
把这种邻点污染视为普通参数相对舍入。其 24 小时粒径变为
**57.56387 µm**，设备按精确节点为 **56.25500 µm**，差 **1.308872 µm**。

NumPy 和设备现在都在输入的 8 epsilon 舍入范围内识别最近表格节点，
保留原表值；真实插值仍使用原三线性公式。新增节点及相邻浮点数回归，
原失败结果和诊断脚本继续保留。没有修改原始 UCAR 数据，也没有以
改变科学门来隐藏差异。

## 科学误差与守恒

检查使用同量化输入的独立 NumPy64 参考；科学门与
[质量输送报告](CLM_GPU_SNOW_MASS.md)的分段近零口径一致，另检查冰/水
分量和潜热。潜热近零分界 1 J/m²、绝对容差 0.1 J/m²；相态水量
分界 0.001 kg/m²、绝对容差 0.0001 kg/m²。同精度保持
`rtol=atol=1e-6`，整数和标记一致。

4 个干湿老化工况另对照独立 SciPy 自适应 ODE 积分，float32 粒径
相对误差分别为 **0.000001836%、0.000001357%、0.4329951%、0.000000607%**。
三维查表已在 NumPy 对照独立 SciPy 插值器；全表节点额外逐一检查。

扩大工况覆盖 2,035 个水汽工况、4,739 个微结构工况（含全部 2,728
查表节点、随机冻融状态、再冻结历史、长步长压实和空雪沉降）。

极小 tau 附近，float32 状态量化及节点识别仍会影响插值；上述粒径
6.615849% 在 Wang 的 10% 口径内，明确保留，不为追逐更细相对差
改动原始拟合表。中间拟合参数最大绝对差 62.61899（各参数单位不同），
报告仅作诊断，不将它冒充粒径或质量误差。它们仍参与同精度全字段门。

水汽潜热最大绝对差 **16 J/m²**、冰/液水分量差分别
**7.629395e-6 / 6.198883e-6 kg/m²**；近零项独立检查。
double 独立累加的 float32 水/焓预算最大：水汽模块
**1.091138e-5 kg/m² / 1.938110 J/m²**；微结构模块
**8.463860e-6 kg/m² / 2.785156 J/m²**。使用质量输送中的逐操作
浮点预算界，守恒与 10% 科学门分开；沉降输入用 double 乘速率和时长
后审计，包含输入乘法舍入，不能静默丢弃裸地沉降。

水汽模块的 CUDA32/JAX32 全字段最大差 **0**。微结构所有字段通过
同精度门，新雪密度最大绝对差 **0.0003051758 kg/m³**，未要求逐位相同。
目标测试 **8 passed / 0 skipped，20.84 秒**。
最终冻结源码 Linux 全量测试 **475 passed / 0 skipped，300.00 秒**。

三类柱各执行 336 步，每步包括水汽、压实/老化、沉降，四后端合计
**12,096 次柱操作**。全程 CUDA32/JAX32 最大差 **0**。
float32 对 NumPy64 最大层质量差 **0.001175670 kg/m²**、层焓差
**7.479473 J/m²**、厚度差 **5.220734e-6 m**、粒径差 **0.0009223903 µm**。
累计水/焓/杂质残差最大分别为 **3.360874e-5 kg/m²、0.8886964 J/m²、
9.230561e-12 kg/m²**；NumPy64 和 JAX64 累计焓残差分别为
**1.995431e-9 / 1.744411e-9 J/m²**。这是给定交换量的组件过程链，
没有冠层和完整大气能量求解；不能写成四后端完整冬季柱验证。
完整扩大审计含首次编译共 **125.6076 秒**。
