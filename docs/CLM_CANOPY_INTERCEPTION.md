# 分层冠层截留、冻结和水汽质量/焓组件

开发状态：已建立独立 NumPy 参考及原生 JAX/CUDA 十层组件；完整柱仍用共享
液水储量，不能据此宣称整柱已支持冠层截雪或完成 P2。随后新增的
[NumPy焓—叶温联立开发路径](CLM_CANOPY_PHASE_ENERGY.md)已使用分层冰水状态，
其连续验证、GPU同步与完整柱连接仍待完成。连接必须同时处理相变平台、
分层湿润比例、可用相态供水及水汽携热，不能只增加一个冰量字段。

## 方程、单位和边界

依据 [CLM5 Hydrology 技术说明 §2.7](https://escomp.github.io/CTSM/release-clm5.0/tech_note/Hydrology/CLM50_Tech_Note_Hydrology.html)
的截留、容量、雪卸载及蒸发相态关系原创实现；
[CTSM CanopyHydrologyMod](https://raw.githubusercontent.com/ESCOMP/CTSM/master/src/biogeophys/CanopyHydrologyMod.F90)
只读用于理解大气温度卸载阈值和流程，没有复制 Fortran。此链接是访问时的
master，不是固定版本官方模拟输出；独立方程核验不能代替观测或 CTSM 柱输出。

`physics/canopy_interception.py` 的 `CanopyCondensate` 保存逐层质量 M
（kg/m² 地面）与焓 H（J/m² 地面）。焓原点是 273.15 K 的冰；
H<0 为冰显热，0≤H≤Lf M 为融点冰水混合物，H>Lf M 为液水显热。
相变只改变诊断温度和冰水比例，权威状态始终是 M/H。输入降雨、降雪和水汽
均是整步质量，不能把 kg/m²/s 通量直接传入。

暴露叶/茎面积按植被面积定义；植被覆盖比例为 f，面积和为 A。
雨截留比例 f tanh(A)，雪截留比例 f[1−exp(−A/2)]；截留后按各层面积占比
分配质量和携热。这是简化的垂直分配假设，并非 CTSM 的独立逐层水动力方程。
层液水、冰容量分别为 0.1 f A_i、6 f A_i kg/m²。混合后溢出的液水/冰、
透过降水及卸载雪都返回其各自质量和焓，不丢弃融水显热。

卸载比例为 min[1, dt(U/156000 + max(Tair−270.15,0)/187000)]，作用于
容量限制后的冰。270.15 K 与所读 CTSM 实现一致；技术说明写作约 270 K。
卸载量上限是可用冰量；若写成速率则上限应是冰量/dt，保持量纲一致。
湿润比例采用 min[1,(M/(0.1 f A_i))^(2/3)]；可蒸腾干叶比例再乘叶面积
占叶茎总面积的比例。雪覆盖比例采用相对冰容量的 0.15 次幂。

`exchange_vapor` 使用调用者给定的叶温：高于融点取液水，等于或低于融点
取冰（CLM 冠层约定）。正通量受所选相态质量限制，未满足蒸发量显式返回；
负通量按叶温沉积霜/露。输出分别保留凝结相携焓与相变潜热，后续能量求解
需要将二者放入对应边界账目。此组件自身不生成辐射或感热输入。

## 独立 NumPy 核验

`check_canopy_interception_reference.py` 用 50 位 Decimal 独立计算公开
体积截留/卸载关系，覆盖雨、雪、融点卸载、面积、覆盖比例、降水、风速和步长，
共 **1728 工况**。最终 NumPy 源码的最大质量/焓差为
**7.10543e-15 kg/m² / 1.86265e-9 J/m²**；非近零相对偏差最大
**6.69588e-10%**（地面出流质量）。量级接近零时使用预先指定的绝对容差。
逐步水/焓收支最大残差 **7.99361e-15 kg/m² / 1.86265e-9 J/m²**。

365 天、17520 个半小时步显式施加季节/日变化热输入，逐项记录全部热量与
水汽携焓，检查冻融、截留和卸载。最大单步水/焓残差
**1.14492e-16 kg/m² / 3.63798e-11 J/m²**；最大累计残差
**2.44249e-14 kg/m² / 2.79397e-9 J/m²**。期间冰量、液水量最大分别为
0.483036、0.238038 kg/m²。该热输入是规定热源，用来检验守恒，
**不是已完成的叶温辐射平衡，也不是观测验证**。

## 原生后端与数值诊断

JAX/CUDA 输入十层 M/H、叶茎面积、降水/卸载条件及水汽量和叶温，两个原生
模式分别完成截留与水汽交换。host 层只编码、检查与解码，未调用 NumPy 物理
代替设备计算。所有状态、分层通量、相态、覆盖和收支诊断均参与同精度比较。

冻结 `e` 目标测试 **14 passed / 0 skipped，11.38 秒**，68 个设备工况
CUDA32/JAX32 全字段最大差 **0**。float32 单步独立水/焓残差最大
**2.10898e-6 kg/m² / 1.11343 J/m²**，float64 为
**7.10543e-15 kg/m² / 1.86265e-9 J/m²**。按每个工况的浮点储量和边界
项规模检查 `64ε × max(scale,1) + [1e-12 kg/m²,1e-6 J/m²]`；
float32 最大数值界为 0.000882915 kg/m² / 160.915784 J/m²，
这些数值界不是实际误差，未用 10% 豁免守恒。

扩展 **428 工况**和三柱七天（336 步 × 2 过程 × 3 柱 × 4 后端，共
**8064 次柱操作**）已完成，56.68 秒；CUDA32/JAX32 全部输出最大差仍为
**0**。最终 Linux 全量回归 **510 passed / 0 skipped，697.67 秒**，
完整日志 `v1-results/p2-canopy-interception-e-full.log.gz`；此冻结快照不包含
随后开发的冠层焓—叶温联立求解器。
科学门沿用 10% / 近零绝对差；该组件另用严格的 0.001 K 单步温差检查。
同精度门保持 rtol=atol=1e-6，不按 Kelvin 基数放宽温度科学门。

428 工况独立单步最大水/焓残差为 **4.16161e-6 kg/m² / 1.66398 J/m²**。
七天 float32 最大累计水/焓残差为 **2.60632e-6 kg/m² / 0.313394 J/m²**；
float64 为 **1.24345e-14 kg/m² / 1.25729e-8 J/m²**。逐步和累计均按明确的
浮点数值界独立审核；完整实际残差及数值界保留在结果 JSON。

开发中保留了下列失败与修复证据：

- `b`：从大焓量相减求微量剩余水焓，温度差 0.00128729 K；改为直接按
  剩余相态质量比例计算保留焓，再以差值记输出携焓。NumPy 独立参考与全年
  守恒在此修改后重跑，得到上列数字。
- `c`：CUDA wrapper 对 NumPy 数组直接调用 CuPy 连续化接口造成类型异常；
  明确先转换设备数组后修复。此前 JAX32/64 已通过。
- `d`：两个设备的 tanh(3.5) 分别为 0.9981778860、0.9981779456，相差一个
  float32 位。暖雨与负冰焓相消后，层焓差放大至 0.0009765625 J/m²。
  扩展诊断共发现 13 个层焓超差元素，原报告保留。
  `e` 用等价的 `−expm1(−2A)/(2+expm1(−2A))` 统一原生表达式；在 A=0
  处稳定且不溢出，没有改变截留物理、输入、验收门或隐藏收支输出。
