# 可用，带已知限制

本项目是 Noah-MP / CLM 风格单柱物理的 Python 重实现。以下限制随 README
公开；数值后端一致性不等于观测验证，完整 FLUXNET 验证仍属于 Phase 4。
当前生产物理为 `b954d90`，M1 的 ΔT 候选未采用，见[尝试与回退](GPU_DELTA_ATTEMPT.md)。

**本轮发布门尚未通过：** 四站真实数据的 canw 通过率为99.114583%，低于事先固定的
99.5%。因此保留在 `gpu/migration`，不合并main、不打v0.2.0。总体可运行与发布验收
是不同结论；所有失败数字如下公开。

## 真实站点近零冠层水：M4未过硬门

四站各30天、5760柱步中，CUDA32/JAX32的canw有51项超过纯相对1e-3门；
其他八个状态/通量字段均100%通过，JAX64原parity门通过，residual分位数及
表面/水量核算通过。CN-Cha单站42/1440项超差，canw通过率97.083333%。
全部51项已归因：42项冠层干燥时的相对敏感性、9项耗尽舍入，均无雪。
失败项最大绝对差 **2.65310064e-8 m**、失败项两端最大存水 **2.34675564e-5 m**；
全体canw最大绝对差9.42483047e-8 m。参考公式重构误差≤1.69e-21 m，
forcing量化、历史存水、温度路径、本步评价四项分解完整，重组误差为0。
量级很小、原因已知仍不能更改预先固定的99.5%硬门。
见[真实数据结果](REAL_DATA_CHECKS.md)和[逐项归因](gpu-results/m4-canopy-attribution.json)。

## K1 / H4：原严格逐元素门仍红

1024柱×48步的生产 float32 输出，residual 原 `rtol=1e-4, atol=1e-6` 门失败
49145/49152项，对 NumPy64 最大差 .002507086880 W/m²，569项差>.002，均聚集
在无雪暖湿降雨配置。新M2门下，自身残差中位 .000293732、p99 .00181961 W/m²。
H/LE/G 原门分别失败1461/6/18864项；这些红灯保留，不能称原H4全绿。

先前“double割线+F”原型的 **137项残留**不是生产输出：它们对应21个唯一柱步，
融雪初始配置86项、降雨配置51项，但失败当时全部无雪无冰；最大残差后端差
7.88336e-5 W/m²。该原型设备耗时增加59.47%，未采纳。
[K1完整历史取证](GPU_RESIDUAL_FORENSICS.md)保留原始数据。

M2中canw另有153/49152项相对超差，通过率99.6887207%；全部发生于降雨结束后
冠层接近耗尽，超差项最大绝对差1.39334e-11 m，均有公式重算分解。
详见[M2实际数字](GPU_CLOSEOUT_RESULTS.md)。不为这些项增加状态绝对容差。

## K3：冻土与厚雪下土壤温漂

64800柱原域门有 **5565柱（8.58796296%）**有效终态超差，整数一致：
5529柱无雪砂土冻融、36柱厚雪冻土。全部5565个冰量超差的温度轨迹项绝对值
大于公式评价和水量轨迹两项绝对值之和；最大终态冰差约 **5.42444e-4 m³/m³**。
最大逐步地表温度差 .0747771 K、H差2.29383 W/m²、G差2.65781 W/m²。

无雪砂土路径中，AHC的未冻水截断区会放大旧态温度微差；一个冻结状态探针把
.000663833 K的旧态差放大至.194006536 K的新土温差。厚雪下36柱是另一机制：
均温绝热土壤的float32绝对温度Thomas消元累计漂移，最大.002288818 K。
两者都已定位到温度轨迹，不能笼统称为相变瞬时噪声。

**冻土敏感应用建议用 float64 / JAX-x64。** M1一次增量修复触发同精度回归后
已回退；K3以完整归因和公开限制接受，原域门不改绿。
详见[全域取证](GPU_DOMAIN_FIX.md)和[本轮复验](GPU_DELTA_ATTEMPT.md)。

## 整柱融雪热量路由

既有薄雪融尽切片中，G×dt=259524.419335 J/m²，融化潜热36740 J/m²，剩余
**222784.419335 J/m²**未路由到土壤或融水热量。表面能量可以闭合，但整柱焓
不保证守恒。Wang明确接受此范围并要求公开；不适合把本实现当作已验证的
完整雪焓模型。见[年度修复与限制](GPU_ANNUAL_FIX.md)。

## 性能与来源边界

- 旧五档GPU/双卡/profiling表属于 **K2修复前** 源码（JAX `0e296691…`、CUDA
  `7640b062…`），不能称为修复后性能。最新N100000复测另列于[BENCHMARK](BENCHMARK.md)。
- NumPy单核N100000/N300000旧基线分别3616.904161/10272.657723秒；六次checksum
  一致，但进程启动时没有记录已加载源码hash。事后源码核查不能补成运行时来源证明。
  GPU完整输出归约/逐值比较的计时口径与CPU逐柱标量checksum消费也不同。
- 双4090 JAX x32在N100000/64800仅1.04682×/1.08759×，传输、回读及协调主导，
  属预期；x64为1.62227×/1.74957×。未达1.9×，不再把任意扩展目标当验收门。
  手写CUDA双卡未测。
