## 混合精度实验

已在同一冻结源码和同一输入上实测。独立生成器
[probe_mixed_secant.py](../benchmarks/probe_mixed_secant.py)复制F评价及其依赖函数
为double版本，在每柱内提升本步状态、强迫和已算出的蒸腾值；割线25次、回退
扫描/二分及停止标准原样保留，土壤/雪水热更新和存储ABI仍为float32。
完整mixed在double根处评价最终通量/残差后再写回；没有把residual设为零。

| 48步对NumPy64 | 原float32 | 仅double求根、回float32评价F | double求根+F |
|---|---:|---:|---:|
| residual最大绝对差 W/m² | .00250709 | .00210856 | **.0000788336** |
| residual原门失败数 | 49145 | 49145 | **137** |
| residual差>.002 | 569 | 7 | **0** |
| 自身最大\|residual\| W/m² | .00248432 | .00210571 | .000990535 |
| H原门失败数 | 1205 | 1190 | 1192 |
| LE原门失败数 | 6 | 0 | 0 |
| G原门失败数 | 18096 | 18028 | 18103 |
| 最终浮点状态原门失败数 | 0 | 0 | 0 |

完整mixed首步全部12诊断均通过原NumPy64门。48步剩余137项residual对应21个
唯一柱步，其中融雪初始配置86项、降雨配置51项；**实际失败步均已无雪、无冰**，
不能因为初始情景叫“融雪”便将其归为相变失败。第一次出现于第20步，93项。
这显示初始割线量化问题明显改善，但累计状态误差和独立求根停止路径仍须处理，
未证明这些剩余值可以放宽。

[mixed输出](gpu-results/k1-mixed-f716548-mixed.npz)保存全部逐字段结果和生成源码hash。
源kernel SHA256为`7640b062a329bf290c3719a62bddf97ea2ec523167b387730e758b8bd1b40454`。

初测N100000×48、各3预热+3正式、读回全部状态/整数/诊断、每次完整逐位比较：
完整调用中位耗时增加23.7%，未达到预期的<10%。该口径含大量主机输出搬运。
随后用[独立设备计时脚本](../benchmarks/time_mixed_secant.py)交替baseline/mixed顺序，
同样3预热+3正式，输入和全部48步输出均驻留设备，用CUDA events计时48个kernel；
每次计时后实际读回全部状态/整数/诊断并核对SHA256，未只消费小片输出。

设备正式样本baseline为`.0928051224/.0600720329/.0929206696`秒，mixed为
`.147973114/.193731583/.147993500`秒；有波动，但所有mixed样本均比所有baseline
样本慢，不能声称<10%。[设备原始JSON](gpu-results/k1-mixed-device-f716548.json)与
[日志](gpu-results/k1-mixed-device-f716548.log)保留顺序、输出hash和全部预热。
测量时服务器另一张GPU另有正确性作业，不声称整机独占。这是K1新变体成本实验，
不重复或覆盖已冻结的J计时/profiling/双卡成绩。

当前决策：**未采纳生产kernel、未改变容差、H4仍红**。把精度关键路径用float64、
批量物理保持float32是有效的数值设计方向，但本原型还没有满足精度和成本条件。
不能将消除569个历史反例写成原H4通过，也没有基于“相变聚集”提出分档方案。
