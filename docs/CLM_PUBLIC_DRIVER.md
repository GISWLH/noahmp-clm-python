# 完整 CLM 状态接入公开驱动

`noahmp_clm.step_column/run_column/run_columns`现在可直接推进显式
`CLMColumnState`和`GlacierColumnState`，返回形式与既有调用一致：单步为
`(new_state, diagnostic)`，连续为`(diagnostics, final_state)`，批量为各柱结果列表。
完整C/N、作物种子/收获、灌溉请求、甲烷库及瓦片排水参数保留在实际状态内。
调用者传入旧`ColumnState`时仍运行原v0.2物理；不会把完整状态降维到旧70值ABI。

固定的叶参数、测高和VIC参数作为关键字传入；`step_options`为每个强迫间隔
提供一个字典，可显式覆盖固定值，传递CO₂、太阳分配、物候、沉降和管理事件。
批量时使用每柱一个`step_options_list`序列。所有柱/间隔长度及映射类型在
推进前检查，不再通过`zip`静默截掉尾部柱、强迫或管理事件。每柱可有不同步数。
这是NumPy公开驱动；原生JAX/CUDA批量入口继续位于`noahmp_clm.gpu`，本次没有
改变物理核、设备ABI、收敛条件或数值守恒界。

[完整可运行示例](../examples/run_clm_column.py)给出显式示意植物/土壤C/N库、
10层冠层、SNICAR、湿球选项5、VIC选项6和独立测高的MOST反馈。
它运行3个1800秒步，不代表已spinup或已校准站点。CPU示例及测试在EHPC PBS
计算节点执行，本机只编辑、静态核对和整理证据。
