## 接口与守恒

每柱固定五个单元，字段为质量 kg/m²、焓 J/m²、厚度 m、粒径 µm、
亲水 BC 和四类尘埃质量 kg/m²。降雪插入时暂存第六个单元，再重分层。
相态由质量/焓诊断，温度内部用冰点偏移；没有重试旧土壤 M1 的全量
温度增量 Thomas 方案。

五个操作编号分别为 0 重分层、1 降雪、2 雨、3 排水、4 冰升华。
`pack_snow_transfer` 负责将 NumPy 状态转为批量输入；所有相态诊断、
收水体积限制、48 次容量二分、携焓/杂质输出及重分层均在设备计算。
四个独立账目为 incoming、drainage、runoff、sublimation，各自保存
水量、焓和五类杂质。阻水层上方溢流归 runoff，不伪装为穿过冰层的
土壤入渗；升华保留雪内杂质，雪耗尽后把残留交给调用者。

逐操作独立用 double 累加七类收支。硬界为
`32*eps*(sum(abs(old_cells))+abs(new_total)+sum(abs(ledgers))) + floor`，
其中 floor 为水量 1e-10 kg/m²、焓 2e-7 J/m²、各杂质 1e-19 kg/m²。
这是浮点运算界，独立于 10% 科学门，不允许把未路由能量豁免掉。
科学门按参考量是否近零分段：质量 0.001 kg/m² / 绝对容差 0.0001，
焓 1 J/m² / 0.1，厚度 0.0001 m / 0.00001，粒径 1 µm / 0.1，
各杂质 1e-12 kg/m² / 1e-13；超过分界只用 10% 相对门。
CUDA32/JAX32 仍用 `rtol=atol=1e-6`，层数整数一致。

## 找到并修正的问题

1. 初版按“绝对层界相减得到的重叠 / 原厚度”分配内容。深处薄层的
   重叠与原厚度有相对舍入差，导致 float32 9 项杂质预算超过预设界，
   float64 也有 4 项极小杂质超界。现在逐个源层按其实际重叠分配，
   最后一份接收尚未分配的质量、焓、杂质和逆粒径质量代理量。
   薄于绝对层界 ULP 的源层归入其所在目标层。NumPy 与设备均已修正，
   不是在最终柱预算上追加补偿能量。
2. 快速浮点除法中 `water/total` 在相等端点可能不为精确一，造成零
   径流仍携带约 1.819e-12 kg/m² 杂质。现在在完全流向同一路径时
   明确使用完整份额，其余分配限制在 [0,1]。
3. 扩大检查发现 NumPy 参考也有全融化耗尽问题：`water+(liquid-water)`
   可与原质量相差一个 ULP，使残余质量变成负的/消失的小数，而未导出
   的杂质随空层删除。两个原输入的最大杂质丢失分别为
   **0.0001958928 / 0.001897696 kg/m²**。全融化现在精确导出全部液体
   及杂质；保存的失败输入为 `tests/fixtures/snow_melt_tracer_exhaustion.json`。
4. 接收层以实际冰/水总体积准入，但出流端重新计算孔隙率会在饱和
   附近判出虚假溢流：一个样本为 **3.129244e-7 kg/m² / 0.1045167 J/m²**，
   独立 double 参考为零。两端现使用相同的占据体积条件，没有放宽
   预设近零焓门。旧日志全部保留。

## 设备实测

冻结快照 `p2-snow-mass-e`，RTX 4090，设备 UUID
`GPU-e0adbd49-46d5-1291-1415-d208c0926b58`。NumPy 2.5.4、
JAX 0.11.2、CuPy 14.2.0、CUDA 12.4；JAX64/32 和 CUDA32 实际执行。
输入先量化为各后端精度，再交由 NumPy64 参考计算，避免混入不同强迫。

**2,015 个单步工况**（含 2,000 随机工况及保存的全融化失败）通过。
另有八个重分层阈值各三种相邻 float32 数共 24 个工况，同精度和
