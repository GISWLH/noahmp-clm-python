# P1 物理缺口源码审计（2026-10-26）

本审计只检查当前生产源码、已有测试和已封存证据，没有改动物理代码或重跑模型。

- 融雪余热路由已存在于 legacy 三层、JAX、CUDA 和 CLM 五层焓路径。`apply_snow_heat`
  逐层累加 `remaining_heat`，驱动把它作为 `g_soil` 传给土壤热更新；已有 12 工况
 及融尽切片测试通过。封存数字为输入 259524.419335 J/m²、融化潜热 36740、
  入土余热 222784.419335 J/m²，土壤账残差 −6.46396e−8 J/m²。仅保留一个
  直接调用 `swe<=1e−6` 的微量雪早返边界提案，未改代码。
- 冻土 AHC 已有 C1 平滑截断；列级测试把旧 0.194006536 K 放大降到 0.0026350664 K
  （−98.6418%）。完整域仍有 5618 对旧 5529 的状态差异，最大冰量差
  1.314697e−4；这项剩余按已知限制保留，不重复 M1 全量 ΔT 方案。
- 厚雪 Thomas 对均温/零通量路径已有 NumPy/JAX/CUDA 一致的精确不变式；已有
  8100 柱测试最大漂移 0 K，旧 36 项均温失败已消除。非均温砂土路径仍可能有
  float32 漂移，当前不改生产求解器，避免重复已回退的 M1 方案。

这些结论证明 P1 收尾代码路径已有局部修复，但不替代完整年度、HRLDAS、FLUXNET
和 v1.0.0 科学验收。
