# 简化灌溉：NumPy组件开发中

`physics.irrigation`实现土壤水触发和限供水下的定时施水。尚未启用整柱
`OptIrrigation`，原生JAX/CUDA及站点验证待做，不能标作功能完成。

依据[CLM5灌溉说明](https://escomp.github.io/CTSM/release-clm5.0/tech_note/Crop_Irrigation/CLM50_Tech_Note_Crop_Irrigation.html#the-irrigation-model)
式2.26.13–17，以根区目标和萎蔫储水量构造触发阈值，缺额为阈值减实际液水。
根区深度默认0.6 m、阈值比例1。这里直接接收站点目标/萎蔫体积含水量，
默认0.28/0.12对应当前壤土场景；不冒充官方基质势反演结果。边界土层按
落在根区内的实际厚度积分；超过模型底部的根区不凭空增加储量。

调用者显式提供每日检查事件（后续站点适配器在当地6时后触发），不在每个
时间步重复建立请求。默认施水持续6小时是可配置场景假设。待施水量及剩余
时间随状态携带，但只是未填的请求，不是物理水库。实际每步施水不超过
外部可供水量；缺水单独记录，不补造水。裸地或冻根区取消未完成请求。
尚未取用河道/地下水，单柱外部供水必须单独入水量账。

水温显式输入，液水焓为 `mass × [Lf + Cw × (T − Tf)]`。组件输出水量/焓，
后续整柱必须经地表入渗及径流真实路由，绕过冠层截留；不能直接提高土壤含水量。
只处理液态供水，不接受低于融点的输入水温。

NumPy **6 passed，0.25秒**：90组独立Decimal根区缺额对照最大差0 kg/m²；
解析48 kg/m²缺额在12个半小时步施完，每步4 kg/m²。调用实际土壤入渗后，
水残差0 kg/m²、焓残差−3.72529e-9 J/m²。每步限供1 kg/m²时实际12 kg/m²、
未满足36 kg/m²；冻土/收获取消请求不删除物理水量。
证据：[NumPy日志](v1-results/p5-irrigation-numpy-a.log.gz)。
